# 지원서 에이전트 — 운영 규칙

**3단계 지원서(이력서·자소서) 에이전트.** 모든 산출물은 한국어.

## 구조
```
[1] portfolio/     진실 공급원. 기업과 무관, 계속 갱신.
[2] companies/     기업별 JD·회사 분석. 기업마다 폴더 1개.
[3] applications/  질문별 답안. 1+2를 결합.
```
3단계는 경험을 지어내지 않는다. 반드시 `portfolio/` 경험 파일에 근거한다.

## 경험 구조 (1단계)
- `career/ car-*` 경력 · `activities/ act-*` 대외활동 · `projects/ prj-*` 산출물. **경험 1건 = 파일 1개**.
- 연결: 활동 산하 프로젝트는 `activity: act-NN`, 경력 산하 프로젝트는 `career: car-NN` ↔ 상위의 `projects:[]`. 그 외 `related:[]`. 항상 양방향.
- frontmatter 필수: `id`, `category`, `type`.
- `type`: 그 자체로 STAR 하나가 되면 `episode`, 하위 프로젝트를 거느린 기간·소속이면 `container`(STAR 없음이 정상). 판정·섹션은 `/exp-add`.
- **경험 파일엔 현재 사실만 둔다.** 정정·보강 경위(날짜, 예전 기록)는 `portfolio/_history.md`에 쌓는다 — 옛 기록이 섞여 있으면 삭제한 거짓이 다시 재료로 쓰인다. 부정형 사용 제한(⛔ "수상 아님")은 파일에 남긴다.
- **답안 표현 규칙은 `portfolio/_terms.md` 한 곳에**(금지 표현·내부 용어). 사용자가 라벨·통칭·프레이밍을 교정하면 답안만 고치지 말고 즉시 추가한다. 제목·한 줄 요약은 로스터에 매번 보이므로 금지 표현을 넣지 않는다(`_check.py`·`_lint.py`가 검사).
- 모든 파일에 `## 증거 조각`(형식 `` - `[표준태그]` 사실 한 줄 ``, 3~8개). 본문의 파생물이라 함께 갱신한다. 3단계는 여기서 골라 조립한다.

## 저장·정합성
- 원본은 로컬 마크다운. Notion 미러를 쓰면(`profile.md` 「에이전트 설정」에 표시) 충돌 시 로컬 우선.
- `python3 portfolio/_check.py`로 검사한다(경험 변경 후, `/answer` 시작 시, `/retro` 딥 회고 시). **오류 0이 기준.**
- `INDEX.md`는 frontmatter의 파생물. 손으로 고치지 않고 `python3 portfolio/_index.py`로 재생성한다.
- 과거 제출 자소서(외부 보관처)는 미러하지 않고 필요할 때만 조회한다(위치는 `portfolio/profile.md` 「에이전트 설정」). 검증된 사실은 `portfolio/`로 옮긴다.
- 승인된 답안은 `applications/{회사명}/answers.md`에 누적한다(덮어쓰기 금지).

## 세션 운영 (토큰·품질)
API 호출마다 대화 전체가 다시 전송되므로 **세션 길이가 비용과 품질을 가장 크게 좌우한다.** 작업 단위 = 세션 1개, 상태는 파일로 넘긴다.
- 경계: ① 회사 분석 저장 ② 배분 계획 + 항목 기입형 ③ 문항 1개 승인·저장. 경계에서 에이전트가 먼저 session.md를 갱신하고 "새 세션에서 `/answer {회사명} 이어서`"를 제안한다(모든 문항이 저장되면 `/retro`). 끊을지는 사용자가 정한다.
- 인계 파일 `applications/{회사명}/session.md`(형식: `portfolio/_templates/session.md`)는 **현재 상태만** 담는다: 분석 요약(답안 세션의 회사 입력, 원본은 `companies/`)·문항 상태표·배분·이번 지원 전용 지시 / 진행 중 문항의 확정 전략 카드·뼈대·🔒 승인 문장·최신 초안·열린 결정.
- 새 세션은 session.md부터 읽는다. 없는 맥락은 추측하지 말고 묻는다. 🔒 승인 문장은 사용자가 고치라고 할 때만 바꾼다.
- 답안 기계 검사는 `python3 portfolio/_lint.py {회사명}`(고친 뒤 재확인까지 최대 2회). PDF·이미지는 `python3 portfolio/_extract.py <파일> {회사명}`으로 텍스트화해 필요한 쪽만 읽는다. 즉석 검사 스크립트·도구 탐색을 하지 않는다.
- 피드백 저장 위치: 이번 지원에만 → session.md / "앞으로도" → 스킬(지원자 개인 기준은 `profile.md`, 메모리엔 대화 방식만) / 사실 정정 → `portfolio/` 원본.

## 스킬
`/exp-add` 경험 정리(1) · `/company-analyze` 기업 분석(2) · `/answer` 답안(3) · `/retro` 자체 평가·개선

## 핵심 원칙
0. **포지셔닝 먼저.** 답안은 "HR이 이 사람을 뽑아도 되는 이유"를 만드는 글이다. 경험 매칭보다 "나를 어떤 사람으로 세울까"가 먼저 확정돼야 한다(순서를 어기면 전면 재작성). 문항마다 HR의 진짜 판정 질문이 있고, 결정적 약점은 정면으로 방어한다. 그래서 2단계는 **지원 유형과 탈락 사유(사람 단위 리스크)**까지 분석한다.
1. **정량화.** 결과는 숫자·비율·규모로. 없으면 "정량 보강 필요".
2. **사실 불가침 · 표현 재량.** 지원서는 가장 유리하게 말하는 문서다. 금지선은 유리하게 쓰는 게 아니라 **검증 가능한 사실을 다르게 쓰는 것**이다.
   - 🔴 불가침: 없는 경험·역할·직책·수치(부풀린 자릿수 포함)·기간·학력·자격·수상, 없는 인과(무관한 두 사실을 `그 결과`로 잇기), 남의 성과. 검증 한 번에 합격 취소로 돌아온다.
   - 🟢 재량(적극 사용): ①최대 유리 해석(맡았으면 "도왔다"가 아니라 "맡았다") ②선택적 생략(생략은 거짓이 아니다) ③추정 정량(`약·여·이상` + 근거 기록 + 사용자 확인) ④기여 프레이밍(내 몫을 주어로) ⑤사후 재구성(동기·배움은 지금 정리해도 된다) ⑥미래 서술.
   - 판정: **"면접에서 이 문장을 파고들면 진짜 얘기를 이어갈 수 있나?"** 빈 곳은 재량 6종을 다 쓴 뒤 인터뷰로 채운다.
3. **태그**는 `portfolio/TAGS.md` 표준 어휘만. 새 태그는 먼저 정의한다.
4. **근거 추적.** 답안마다 사용·제외 경험 ID와 이유를 남긴다.
5. **연결 활용.** 활동↔프로젝트를 따라가 소속 맥락과 구체 성과를 함께 쓴다.
6. **선별.** 기본 1~2개. 고정 상한은 없고 지면(문항 수 × 글자 수)이 상한을 정한다. 반증 가능한 3-테스트로 판정한다: ①**제거**(빼도 논지가 버티면 장식) ②**한 줄 관계**(경험들의 관계를 한 문장으로) ③**첫 문장 연결**(문단 첫 문장만 이어 읽어 논지가 흐르는가). 죄는 개수가 아니라 연결 없는 병렬이다. 글자가 남으면 경험을 늘리지 말고 A·R을 판다.
7. **재조립.** STAR는 재료다. 문항에 맞춰 강조점을 옮기되 사실은 만들지 않는다. 새 사실은 `/exp-add`로 원천부터.
8. **자체 평가.** 산출물마다 원칙으로 채점한다. 기록 규칙은 `/retro` 「기록 규칙」(시스템 결함만 `IMPROVEMENTS.md`, 두 번째 발생이면 규칙화).
9. **전달력.** 읽히지 않으면 없는 것과 같다(1차 검토자는 비전문가일 수 있다). JD에 있는 말은 표기까지 그대로 쓰고, 없는 말(전 직장·프로젝트 고유 용어)은 풀어 쓴다. 한 문장 = 한 메시지로 짧게 쓰되 논리 관계를 살려 잇는다(세부는 `/answer` 문체). 수치는 뭉개지 않는다. **사용자가 승인한 문장은 규칙보다 우선한다** — 어긋나면 규칙을 고친다.
10. **직무 중립.** 스킬·원칙에 특정 회사·직무·경험·지원자 상황을 박지 않는다(예시도 일반화). 지원자 개인에게만 맞는 판단 기준은 `profile.md` 「에이전트 설정」에. 회사별 내용은 `companies/`, 지원별 산출물은 `applications/`에만. 지원 유형(직무 정합/인접 이동/전환)은 매번 새로 판정한다. **문체 톤은 승계하고 전략은 승계하지 않는다.**

## 규칙 파일 관리 (최적 상태 유지)
규칙 파일(이 파일, `.claude/skills/*/SKILL.md`)은 매 세션 컨텍스트를 차지한다. 길어질수록 비용이 늘고 규칙끼리 부딪힌다. 그래서 **쌓지 않고 고친다.**
- **자리를 가린다**: 원칙 → 이 파일 / 절차·판정 기준 → 스킬 / 기계로 셀 수 있는 형식 규칙 → `_lint.py`·`_check.py` / 개인 설정 → `profile.md` / 이번 지원 지시 → session.md / 시스템 결함 → `IMPROVEMENTS.md` / 경위·날짜 → `_history.md`·answers.md 「개정 이력」. 같은 규칙을 두 곳에 쓰지 않고 이름으로 가리킨다.
- **순증 0**: 규칙을 추가하면 기존 문장을 합치거나 대체한다. 지우는 순서는 사례 각주 → 중복 → 스크립트가 대신하는 설명 → 효과 없던 규칙. ❌/✅ 예시는 품질을 만드는 부분이라 남긴다.
- **분량 예산**: 파일별 상한은 `_check.py`의 `DOC_BUDGET`이 검사한다. 예산 안에서 풀 수 없으면 반영을 멈추고 사용자에게 증액을 제안한다(파일, 현재→요청 상한, 이유). **승인 후에만** 상한을 올린다.
- 규칙을 바꾸면 `python3 portfolio/_check.py --sync`로 Codex 사본(`AGENTS.md`, `.agents/`)을 맞춘다.
