# 태그 용어집 (Tag Taxonomy)

> 경험 frontmatter의 `tags`와 `INDEX.md` 태그별 인덱스가 사용하는 **표준 어휘**.
> **규칙: 태그는 반드시 이 목록에서만 고른다.** 새 태그가 필요하면 먼저 여기에 추가·정의한 뒤 사용한다. (동의어 분산 방지)
> 2단계 `/company-analyze`가 JD 역량을 이 어휘로 매핑하고, 3단계 `/answer`가 이 어휘로 경험을 매칭한다.

## A. 직무·도메인
> 본인 분야의 도메인 태그는 여기에 추가한다(예: `클라우드기획 ⊂ 기획`처럼 상위 태그와의 관계를 「관계」에 함께 적는다).

| 태그 | 정의 | 사용 시점 |
|------|------|-----------|
| 기획 | 요구사항 정의·정책·플로우·화면 설계 등 기획 행위 전반 | 서비스/제품을 기획한 경험 |
| PM | 프로젝트/프로덕트를 책임지고 일정·이해관계자·우선순위를 주도·관리 | 끝까지 책임지고 굴린 경험 |
| 기술이해 | 제품·서비스의 기술 구조를 이해하고 기획·분석에 쓰는 역량 | 기술 제약을 요건으로 옮긴 경험 |
| 보안 | 보안·컴플라이언스(취약점·접근제어·인증 등) 관점 | 보안/규제를 고려한 경험 |
| AX | AI를 업무/조직에 도입·전환 (AI Transformation) | AI로 일하는 방식을 바꾼 경험 |
| DX | 디지털 전환·프로세스 디지털화 (Digital Transformation) | 수기/아날로그를 디지털로 |
| AI에이전트 | LLM 에이전트 설계·구축(프롬프트·워크플로우·자동검증) | AI 에이전트를 직접 만든 경험 |
| 자동화 | 반복 업무·프로세스를 도구/시스템으로 자동화 | 비효율을 자동화로 개선 |
| 마케팅 | 콘텐츠·홍보·캠페인 기획 | 마케팅/콘텐츠 경험 |

## B. 역량·일하는 방식
| 태그 | 정의 | 사용 시점 |
|------|------|-----------|
| 문제해결 | 근본 원인을 진단해 해법을 도출 | 문제를 풀어낸 경험 |
| 분석 | 데이터·경쟁사·시장·로그 분석 | 깊이 분석·파고든 경험 |
| 데이터 | 데이터(설문·지표·A/B)로 의사결정·검증 | 데이터 기반 판단 |
| 고객지향 | 고객/사용자 Pain Point 중심 사고 | 사용자 관점에서 개선 |
| 주도성 | 시키지 않아도 먼저 제안·시작 (initiative) | 주도적으로 시작한 경험 |
| 실행력 | 끝까지 완수해 결과를 내는 execution | 실행으로 결과를 낸 경험 |
| 커뮤니케이션 | 이해관계자 설득·조율·전달 | 설득·전달 경험 |
| 협업 | 팀·타직군과 함께 결과를 만듦 | 협업/팀 프로젝트 |
| 리더십 | 팀을 이끌고 역할을 분배·운영 | 팀을 이끈 경험 |
| 갈등조정 | 이견·충돌을 조율해 합의 도출 | 갈등을 푼 경험 |
| 위기관리 | 돌발·리스크 상황 대응·예방 | 위기/돌발 대응 |
| 실패극복 | 실패를 분석해 다음 성과로 전환(피벗 등) | 실패→극복 스토리 |
| 성장 | 부족함을 스스로 채우는 학습·성장 의지 | 자기주도 성장 |

## 관계 (매칭 시 확장)
질문을 매칭할 때, 상위 개념으로 물으면 하위/동반 태그도 후보로 끌어온다.
- **AI에이전트 ⊂ AX** — "AI 적용" 질문엔 `AX`·`DX`·`AI에이전트`·`자동화` 묶음 전부.
- **PM ↔ 기획** — 동반하나 구분: PM=관리·주도, 기획=설계 행위.
- **주도성 ↔ 실행력** — initiative(시작) vs execution(완수). 둘 다면 둘 다 단다.

## 폐기·금지 (동의어 통합)
- ~~업무효율화~~ → **자동화** 로 통합. (업무효율화 태그는 쓰지 않는다)

## 유지 규칙
- 태그를 새로 만들거나 이름을 바꾸면 **이 파일을 먼저 고치고**, 그다음 경험 frontmatter와 `INDEX.md` 태그별 인덱스에 같은 이름으로 반영한다.
- 의미가 겹치는 태그를 새로 만들지 말고, 위 목록에서 가장 가까운 것을 쓴다.
