# /company-analyze — 기업 분석 (2단계)

입력은 **회사명 + 지원 직무 + JD(원문·URL)**면 충분하다. 회사 자료는 직접 찾는다. 산출물은 용도별로 나누고, 헤딩은 `portfolio/_templates/company/`를 따른다(회사마다 같은 자리에서 찾을 수 있게):

| 파일 | 용도 | 누가 읽나 |
|---|---|---|
| `jd-compare.md` | **어디에 지원할까** — 모집 직무 전체 목록·배제 근거·비교 JD 원문·적합도 | 직무를 고를 때만 |
| `jd.md` | **지원한 직무** — 그 JD 원문·키워드·HR 관점·문항 | 답안의 원본 |
| `context.md` | 회사 — 인재상·톤, 사업·수익 구조, 조직 실체 | 답안의 원본 |
| `fit-matrix.md` | 요구 역량 ↔ 내 경험 | 답안의 원본 |
| `sources/` | 원자료 — PDF·서식·작성 안내·캡처와 그 추출 텍스트 | 필요할 때만 |

## 0. 회사 리서치 (필수)
- **채용 구조부터 확인한다** — 분석의 틀이 여기서 갈린다. jd.md 맨 위에 적는다.
  ① 지원 단위: 직군 / 상세 직무 / 트랙 / 통합채용(직무 분리 없음) — 순위·대응도는 **실제로 고를 수 있는 단위**로 계산한다.
  ② 지망 수·중복지원: 단일 지원이면 선택이 비가역이다. 복수 지망을 기본으로 가정하지 않는다.
  ③ 문항 공개 여부: 로그인 뒤라 못 봤으면 (c)를 "예상 문항"으로 두고 확정 시 갱신한다.
  ④ 회사가 명시한 작성 규칙(공고·작성 안내) — 그대로 판정 기준이 된다.
  ⑤ 서류 밖 전형(필기·과제·코딩테스트) — 직무 선택과 준비를 바꾼다.
- **모집 직무 전체 목록을 먼저 확보한다.** 사용자가 준 JD는 전체 선택지가 아니다. 배제한 직무마다 근거 1줄(jd-compare.md, 후보가 하나뿐이면 jd.md 끝에 짧게).
- WebSearch·WebFetch로 당해년도 우선: 신년사·CEO 메시지(방향·톤 — **화자가 지금도 그 자리인지** 확인), 인재상, 사업 구조·수익원·실적, 최근 전략 이슈, 지원 조직·제품의 실체(같은 부문의 **형제 JD도 읽는다** — 조직이 실제로 굴리는 시스템·플랫폼이 거기 드러난다).
- **출처 링크를 항목마다.** 원문이 막히면 다른 매체로 교차 확인하고 경위를 적는다. 추측을 회사 사실로 쓰지 않는다.
- **PDF·이미지는 Read로 직접 보지 않는다.** `python3 portfolio/_extract.py <파일> {회사명}` → 목차 → `--find` → `--page`로 필요한 쪽만. 원자료는 `sources/`에 둔다. 인용할 수치·필수 요건은 원본 쪽으로 확인한다.
- 찾아도 자료가 없을 때만 context.md 폴백을 쓴다.

## 1. jd.md (지원한 직무만)
- JD 원문, 필수/우대/핵심 키워드(**표기 그대로**), 원하는 사람상 한 줄, 확정된 문항·서식. 지망을 여럿 쓰는 지원서면 지망별 섹션으로 나누고 HR 관점도 지망별로 쓴다.
- 필수역량마다 **스펙형**("~경험")/**성향형**("~을 즐기는 분")을 표시한다.
- **HR 관점 (냉정하게)** — 역량은 다 충족인데 사람 단위로 남는 물음표를 찾는다. 사실 아닌 약점은 만들지 않는다.
  - (a) **지원 유형** 먼저: 직무 정합(현재=지원 직무, 리스크 "왜 이 사람·왜 우리 회사") / 인접 이동(도메인 같고 역할 다름, "그 역할은 안 해봤잖아") / 전환(둘 다 다름, "왜 바꾸나·적응"). 먼저 **채용 전체에 정합 자리가 있는지** 보고, 없으면 그 사실을 대전제로 적는다. 근거에는 **어느 축이 다른지**(역할 / 도메인)를 적는다 — 역할은 같고 도메인이 다른 경우도 있다. 애매하면 리스크 큰 쪽. **직전 지원의 판정을 재사용하지 않는다.**
  - (b) **탈락 사유 Top 3** — `profile.md`·`INDEX.md` 기준. 순위 | 사유 | 성격(정합도/기술 공백/깊이/차별화) | 방어 가능성(서류/면접만/불가). 지원자의 현재 상태(재직/구직/졸업예정)를 적고 `profile.md` 「에이전트 설정 → 지원자 상황 규칙」을 반영한다.
  - (c) **문항별 검증 의도** — 문항 | 표면 질문 | 실제 판정. 유형에 따라 달라진다. 문항 없는 전형이면 서식이 요구하는 축을 넣는다. **문항 배분도 판정 축이다**(문항 하나를 통째로 준 주제 = 회사가 지금 미는 과제). 문항 수 × 글자 수로 **문항당 경험 상한**을 정한다(2~3문항·1,000자 이하면 1~2개).
  - (d) **결정적 리스크 방어** — 서류에서 막을 것 / 면접으로 넘길 것. 서류에 긴 해명을 넣지 않는다(약점을 부각한다) — 무력화하는 프레임을 세우고 정황은 면접으로.

## 2. context.md (`/answer` 키워드 축②③)
- [축②] 인재상·톤: 올해 미는 방향·가치, 회사 톤.
- [축③] 사업·수익 구조 (필수): 무엇으로 돈을 버는지, **내 직무가 어디에 닿는지** 한 줄.
- 지원 조직·제품의 실체, 인용할 키워드·문장. 항목마다 출처.
- 폴백: 자료가 없으면 JD·모집요강의 간접 신호로 채우고 상단에 `TODO: 자료 확보 시 보강`.

## 3. fit-matrix.md
- 먼저 `profile.md`(정형 요건)와 `skills.md`(기술 스택·숙련도)를 대조한다.
- JD 역량을 `TAGS.md` 표준 태그로 환산해 매칭: 요구 역량 | 태그 | 경험 ID | 강도(✅/△/✗/⚠️) | 메모.
- 강점/공백 분리, 공백엔 `/exp-add` 제안. **전부 ✅여도 지원 유형·탈락 사유를 요약에 다시 싣는다**(낙관 편향 방지).

## 4. jd-compare.md (후보 직무가 2개 이상일 때)
- **순위의 주 기준은 ① 수행업무 대응도 ② 직무 성격 적합**이다. ①은 수행업무 불릿마다 경험 ID를 붙여 대응 없는 불릿 수를 센다(상/중/하). ②는 직무의 결(개발/기획/운영/영업)이 지원자가 실제로 해 온 일과 맞는지 — 우대 요건을 다 채워도 결이 다르면 올리지 않는다.
- 적합도 %는 **참고치**다. 필수 목록이 없거나 범용 소프트스킬뿐인 JD, 요건 수가 크게 다른 직무 간 비교, 여러 트랙이 묶인 공고에서는 %를 결론에 쓰지 않는다.
- 적합도% = Σ(점수×가중치)/Σ(1.0×가중치)×100. 점수 ✅1/△0.5/✗0/⚠️ 미확인 0.5(캐럿), 가중치 필수 2·우대 1. % 옆에 근거 1줄.
- 우대 불릿이 적거나 ⚠️가 많으면 상/중/하+근거로. ±10%p 이내면 "우열보다 결이 다름". 결론: 최적 JD 1개와 이유(순위형 지원서면 이게 1·2지망 근거).
- **복수 지망 조합**: 지망들을 한 문장으로 묶을 수 있어야 한다(흩어진 조합은 리스트 자체가 "아무 데나 넣었다"는 반증이다). 하위 지망은 "붙으면 실제로 갈 자리인가"로 고른다 — 재직 중이면 안전판 논리가 성립하지 않는다.

## 5. 분석 요약 → session.md (종료 시 필수)
`applications/{회사명}/session.md`(템플릿: `portfolio/_templates/session.md`) 「지원 공통 → 분석 요약」에 **3천 자 안팎**으로 적는다. `/answer`는 이것만 읽고 시작하고, 출처·세부가 필요할 때만 원본을 연다. 원본을 고치면 요약도 맞춘다.
- 채용 구조 / 지원 직무·순위 / 지원 유형 + 근거 / 문항·글자 수 + 문항별 HR 판정 질문 + 문항당 경험 상한
- 탈락 사유 Top 3 + 방어 방향 / 필수역량(스펙형·성향형) + JD 키워드(표기 그대로)
- 인재상·톤 키워드 / 사업·수익 구조와 내 직무의 접점 한 줄 / fit 강점·공백
- 분석 중 받은 이번 지원 전용 지시는 「이번 지원 전용 지시」 섹션에, 문항별 HR 판정 질문은 문항 표에 적는다

## 자가 평가 · 출력
- `/retro` 루브릭 B로 점검해 채팅으로 보고한다. 다른 회사에서도 재발할 시스템 결함만 `IMPROVEMENTS.md`에.
- 출력: 생성 파일 / 회사가 원하는 것·내 강점·공백 / 지원 유형·탈락 사유·방어 방향 / (후보 여럿이면) 순위와 추천. 끝에 "새 세션에서 `/answer {회사명} 이어서`로 시작하면 리서치 원문이 빠져 토큰이 줄어듭니다"를 한 줄로 제안한다.
