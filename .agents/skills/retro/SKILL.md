# /retro — 자체 평가·개선 루프

산출물과 시스템을 원칙으로 채점하고, 개선점을 `IMPROVEMENTS.md`에 기록한 뒤 합의된 개선을 반영한다.

## 언제
- **인라인**: `/answer`·`/company-analyze` 산출 때마다 빠르게 채점하고 개선점 1~2줄만 보고한다(흐름을 끊지 않는다).
- **딥 회고**: `/retro`를 직접 부르면 최근 산출물 여러 건과 시스템 전체를 본다.

## 루브릭 A — `/answer`
형식 항목(글자 수·소제목 형식·문장 길이·금지 표현·🔒 보존·복붙)은 `python3 portfolio/_lint.py {회사명}`(저장본은 `--all`) 결과를 쓴다. 나머지:
0. **유형 경로** — A~D를 가려 그 경로를 탔나. B·C를 STAR로 길게 풀거나 D에 서사를 붙이지 않았나.
1. **포지셔닝** — 전략 카드를 답안보다 먼저 확정했나. 본문이 포지셔닝을 증명하나. **반박 방어가 전략 카드에만 있고 본문엔 빠지지 않았나**(가장 흔한 누락).
2. **사실·재량 (양방향 감점)** — 🔴 없는 경험·수치·자격·인과, 남의 성과가 없나(문장마다 "면접에서 이어갈 수 있나", 수치는 `_lint.py` 「원본에 없는 수치」). 🟢 사실이 있는데 약한 어휘로 눌러 쓰거나 추정 정량 자리를 비우지 않았나. 과소 서술도 감점이다.
3. **선별** — 3-테스트(제거·한 줄 관계·첫 문장 연결)를 통과하나. 글자 수를 채우려 경험을 늘리지 않았나.
4. **재조립** — 무게중심에 맞춰 재배치했나. 조각을 문장째 옮기지 않았나("다른 회사에도 그대로 들어갈 문장인가").
5. **정량·근거** — R에 수치가 있나(없으면 공백을 표시했나). 사용·제외 ID와 이유를 밝혔나.
6. **기업핏** — 4-B에서 심기로 한 JD·인재상·사업 구조 키워드가 본문에 있나. 지원서 전체로 빈 JD 축이 없나(`_lint.py --coverage`).
7. **매칭 완전성** — INDEX 카테고리 표 전체와 태그 밖 경험까지 봤나.
8. **중복·편중** — 같은 회사 다른 문항과 각도·문장이 겹치지 않나. 개별 ID와 계열 두 단위로 셌나(분모는 서술형만, `_usage.py`의 `[서술형만]` 줄). 정당한 편중(직무·경력 문항에서 유일·압도적 적합)과 관성 편중(범용 문항)을 구분했나. 가져온 단위(container/project)가 문항에 맞나.
9. **구성** — 두괄식인가. 마무리가 새 사실 없이 역량·검증으로 닫히나. `그 결과`가 실제 인과인가.
10. **전달력** — 자르며 논리 관계를 버려 끊긴 곳이 없나. JD 용어는 표기까지 살리고 JD 밖 용어만 풀었나. 쉽게 쓴다고 수치를 뭉개지 않았나. 명명이 질문 종류(지식·기술 vs 태도)와 맞나.

## 루브릭 B — `/company-analyze`
0. 리서치를 직접 하고 출처를 달았나. 모집 직무 전체를 확인했나. PDF·이미지를 `_extract.py`로 읽었나.
1. JD 역량을 표준 태그로 환산했나. `profile.md`·`skills.md`를 먼저 대조했나.
2. 강점/공백을 분리하고 공백에 `/exp-add`를 제안했나.
3. context가 인재상·톤과 **사업·수익 구조**를 잡았나.
4. 지원 유형을 이번 JD로 새로 판정했나(직전 지원의 관성 금지).
5. 탈락 사유 Top 3·문항별 검증 의도를 냉정하게 채웠나. 전부 ✅여도 사람 단위 리스크를 짚었나.
6. 파일을 용도대로 나눴나(직무 고르기 → jd-compare, 지원 직무 → jd, 원자료 → sources/). session.md 「분석 요약」을 채웠고 원본과 어긋나지 않나.

## 루브릭 C — 시스템 정합성 (딥 회고)
```bash
python3 portfolio/_check.py                 # 포트폴리오 정합성 + 규칙 파일 분량 예산·사본 동기화 (오류 0)
python3 portfolio/_usage.py {회사명}         # 회사별 사용 이력·편중
python3 portfolio/_lint.py {회사명} --all    # 저장 답안 형식 (승인 답안이 ❌면 규칙-승인 불일치 → 규칙 수정 검토)
```
- `_usage.py`의 "섹션 못 찾음"(집계 누락)·"유형 미기재"(분모 부풀림) 경고는 answers.md를 `/answer` 「저장」 포맷으로 고친다.
- 스크립트가 못 보는 것: 조각이 본문의 파생물인가(자평 섞임·낡음) · 커버리지 경고가 태그 누락인지 진짜 경험 부족(`INDEX.md` TODO)인지 · 고립 경험(억지 연결 금지) · session.md가 실제 상태와 맞나(저장된 문항이 ◐로 남지 않았나).

## 루브릭 D — 규칙 파일 관리 (딥 회고, 그리고 규칙을 고칠 때마다)
AGENTS.md 「규칙 파일 관리」를 따른다.
- **자리**: 원칙 → AGENTS.md / 절차·판정 → 스킬 / 셀 수 있는 형식 → 스크립트 / 개인 설정 → profile.md / 사례·경위 → IMPROVEMENTS.md. 두 곳에 같은 규칙이 있으면 한 곳만 남기고 이름으로 가리킨다.
- **순증 0**: 새 규칙을 넣으면 기존 문장을 합치거나 대체한다. 사례 각주는 교훈만 원칙으로 올리고 삭제한다. 규칙끼리 부딪히는 문장이 없는지 본다.
- **예산**: `_check.py` `[10]`이 파일별 상한을 검사한다. 넘치면 반영을 멈추고 사용자에게 증액을 제안한다(파일, 현재→요청, 이유). 승인 후에만 `DOC_BUDGET`을 올린다. 반영 후 `_check.py --sync`.
- **메모리**: 중복 병합, 죽은 사실 삭제, MEMORY.md ↔ 파일 1:1(`consolidate-memory` 스킬). 여러 지원에 쓰일 피드백은 스킬로 옮기는 게 맞는지 본다.
- `IMPROVEMENTS.md`는 로드되지 않는 이력 로그라 급하지 않다. 읽기 힘들면 오래된 ✅를 하단 요약으로 옮긴다.

## 절차
1. 대상을 루브릭으로 채점한다(항목별 ✅/⚠️).
2. 미흡 항목을 `IMPROVEMENTS.md` 백로그에 적는다(영역·관찰·조치, 🔵). 포트폴리오 내용 공백은 `INDEX.md` TODO로.
3. 바로 고칠 수 있는 시스템 개선은 반영하고 ✅로 바꾼다(INDEX 재생성 규칙·루브릭 D 준수).
4. 판단이 필요한 건 사용자에게 제안한다.

## 출력
채점 요약(항목별 ✅/⚠️) · IMPROVEMENTS 추가·갱신 항목 · 반영한 개선과 결정이 필요한 제안.
